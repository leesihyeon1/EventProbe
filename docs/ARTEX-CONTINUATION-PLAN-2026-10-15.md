N1 개정 이력: 신규·기존 템플릿의 첫 버전을 보존하고, 현재 새 작업 양식으로 개정할 때 새 버전을 추가한다. 과거 버전 복원은 기존 이력을 덮어쓰지 않고 다음 버전으로 기록한다. 이력 조회·복원에도 같은 작업공간 범위가 적용되며, UI에는 버전/이름/분류만 텍스트로 표시한다. 실행은 별도 확인 후에만 시작한다.

P4 목록 보완: 일반/보관 실행 목록은 작업공간 소유자 필터를 SQL에서 먼저 적용하고 그 결과의 최근 50건을 반환한다. 타인 작업 50건 이상이 최신 목록을 채워도 소유자의 오래된 작업이 누락되지 않도록 합성 검증했다.

N5/P3 경계 보완: 보관 플래그 변경은 저장소에서 상태 조건과 함께 원자적으로 적용한다. 재개 선점 역시 같은 저장소 조건에서 보관·가져온 증거 전용 작업·철회된 승인 계획을 거부한다. 보관 직후 재개와 재개 직후 보관 순서의 합성 테스트에서 대상 요청 0건과 저장 상태 보존을 확인했다. 선점 실패 시 재주입 자격증명을 메모리에 보관하거나 허위 세션 재개 이벤트를 기록하지 않는다.

N7 조회 보완: 초기에는 그래프·사이트맵·커버리지·타임라인 탭의 변경 없는 폴링에만 경량 상태를 적용했다. 아래 후속 단계에서 이 탭의 최초 전체 스냅샷 전송도 제거했다.

N7 목록 보완: 서버 목록 페이지는 실행 데이터 JSON 전체를 Python으로 옮기지 않고 필요한 이름·목표·분류·소유자·보관 상태만 SQLite에서 추출한다. 1 MiB 합성 원문이 저장된 작업도 목록 응답에는 원문이 포함되지 않고 40건 페이지 크기가 제한됨을 검증했다.

P3 승인 감사 보완: 고정 승인 계획이 실제로 수락된 시점에 계획 지문·정책 버전·만료 시각의 `plan_approval` 이벤트를 한 번 기록한다. 만료·거부된 계획에는 승인 이벤트를 기록하지 않으며, 기존 철회 이벤트와 함께 로컬 기록에서 승인 수명을 확인할 수 있다. 작업공간 이름은 인증 신원이 아니므로 승인자의 실명 감사는 사내 인증 연동 후 가능하다.

N3 계획 보류: 실행 중 계획에 이유를 입력하면 `POST /api/agent/runs/{id}/plan/hold`가 현재 요청을 취소하고 단계·계획 지문·정책 버전과 이유를 감사 이벤트로 남긴다. 보류는 자동 재개하지 않는다. 작업공간 접근을 확인하고, 중단된 요청의 처리 여부가 불명확하면 기존 체크포인트 규칙대로 재시작 시 그 단계를 자동 재전송하지 않는다. 화면에는 계획 기록이 시작된 실행에만 보류 버튼을 활성화한다. 보류와 승인 철회 후 최신 결론 이벤트도 새 중단 사유로 갱신한다. 단계별 추가 검사 승인/거절과 인증된 승인자 기록은 아직 남아 있다.

P4 사건 목록 보완: 사건 목록도 작업공간 소유자 범위를 최근 100건 제한 전에 SQL에서 적용한다. 다른 작업공간 사건 105건이 최신 목록을 채워도 내 사건과 소유자 미기록 사건이 반환되는지 합성 검증했다.

N4 사건 탐색 보완: 수동 수집 사건은 서버에서 소유 범위를 적용한 뒤 생성시각·ID 커서로 ‘사건 더 보기’를 조회해 100건 이후 기록까지 탐색한다. 기존 `offset`/`limit` 계약도 유지한다. 요청·요약 원문 JSON 대신 제목·출처·자산/트래픽/외부 ID와 시각만 추출한다. 125건과 큰 합성 요약에서 원문 목록 반출이 없는지, 페이지 사이에 새 사건이 삽입되어도 기존 항목의 누락·중복이 없는지 검증했다.

N7 경량 상태 보완: 기록 탭의 빈번한 상태 폴링은 실행 JSON 전체를 Python으로 읽지 않고 필요한 상태·계획 체크포인트·계수만 SQLite에서 추출한다. 작업공간 접근 검사도 전체 실행 대신 소유자 필드만 읽는다. 합성 테스트는 상태·범위 검사에서 `Store.get` 전체 로딩이 발생하면 실패하도록 확인한다.

N7 발견 조회 보완: 새 작업 상세는 기본으로 기록 탐색 탭을 열어 첫 조회부터 이벤트 메타데이터를 커서로 받는다. 발견 탭은 상태·서버 계산 발견·결론만 받고 원문 이벤트 배열을 응답하지 않는다. 발견의 증거 링크를 열면 기록 탭에서 해당 이벤트 한 건만 조회한다. 발견 분류 변경 응답도 경량 결과로 제한한다. 서버 계산도 관측 본문을 읽지 않고 행동·관측 ID·판정·분류 변경에 필요한 필드만 SQLite에서 추출한다. 전체 스냅샷과 결과가 같은지, 합성 100 KiB 이벤트 원문이 발견 응답과 계산 입력에 없는지 확인했다. 실행 상태 JSON의 전체 조회, 그래프·사이트맵·커버리지와 사용자가 선택한 타임라인 탭의 최초 전체 스냅샷 및 브라우저 실측은 남아 있다.

N7 상세 탭 경량화: 그래프·사이트맵·커버리지는 최초에 경로/판정/증거 연결 메타데이터만 받는다. 요청 헤더·본문·응답 본문·입력 값은 지도 응답에서 제외하고, 큰 HTTP 본문은 Python JSON 디코딩 전에 SQLite 조회에서 제거한다. 그래프 노드 또는 연결 증거를 열 때 원본 이벤트 한 건을 가져온다. 타임라인은 결론 요약과 이벤트 커서 페이지를 사용하고 각 이벤트를 펼칠 때만 원문을 가져온다. 이전 문단의 최초 전체 스냅샷 잔여 항목은 이 단계에서 해소했다. 지도 모델 계산의 일부 작은 메타데이터와 실행 상태 JSON은 아직 서버에서 전체 조회하며, 운영 브라우저/DB 실측은 남아 있다.

N1 템플릿 탐색 보완: 템플릿 검색·분류 결과를 서버에서 페이지로 조회하고 화면에서 ‘템플릿 더 보기’로 100건 이후 기록을 탐색한다. 목록은 명세 전체 대신 표시·정책 판정에 필요한 필드만 SQLite에서 추출한다. 125건의 합성 템플릿에 대해 두 페이지의 ID 누락·중복이 없는지 확인했다.

N1 일괄 관리 일부: 현재 화면에서 선택한 최대 50개 템플릿의 분류를 일괄 변경한다. 서버는 각 템플릿의 작업공간 범위를 개별 확인하고 성공·실패를 따로 반환하며, 성공 항목마다 새 개정 버전을 남긴다. 이 동작은 검증 실행을 시작하지 않는다. 운영 개정/승인 정책과 다른 일괄 작업은 별도다.

N1 자격증명 경계 보완: 템플릿 저장소가 직접 저장·개정하는 명세에도 요청/행위자 헤더 제거를 강제한다. 기존 DB의 템플릿과 개정 이력도 최초 이전 때 헤더를 제거하며, 과거 버전을 복원해도 다시 보존되지 않는다. 명세의 기타 자유 텍스트에 임의로 기입된 비밀값까지 자동 식별하는 기능은 아니다.

이 메모는 P3/N2/N3/N5/N7 전체 완료를 뜻하지 않는다. 단계별 승인/취소 이력의 확장, 대량 데이터 실측과 운영 자동화/인증 연동은 아래 표대로 남아 있다.

기준: 2026-10-15, 브랜치 `harden/access-guard-scoring-tests`, 원격 기준 코드 `d56bad1`과 현재 미커밋 변경. 이 문서가 이전 [구현 인계](ARTEX-IMPLEMENTATION-HANDOFF.md)의 오래된 상태 표보다 우선한다. 상세 기능 근거와 전체 후보는 [필수 확장 검토](reviews/2026-10-15/artex-essential-expansion-review.md), 데이터 경계는 [통합 검토](artex-integration-review.md)를 따른다. 로컬 ARTEX 소스 경로 `D:\ARTEX-main\ARTEX-main`은 다른 PC에 없을 수 있으므로, 이 문서의 요구사항을 구현 기준으로 삼고 참조 소스는 선택적으로 다시 확보한다.

## 바꾸지 않을 경계

- Python/FastAPI와 기존 프런트엔드를 유지한다. ARTEX의 Go 코드를 복사하거나 실제 내부 대상으로 자동 실행하지 않는다.
- NVIDIA는 외부 추론 API다. 내부 도메인·URL 값, 요청/응답 원문, 헤더 값, 인증정보, 캡처/HAR 및 응답 유래 민감 텍스트를 모델·임베딩·외부 로깅으로 보내지 않는다. 외부 AI는 허용된 비식별 구조로 계획을 만들고, 실행/판정/증거 보관은 로컬에서 한다. 반출 허용 필드는 제품 정책으로 명시하고 전송 직전에 검증한다.
- 실제 대상 요청, 운영 DB, NVIDIA 호출은 명시적 승인과 별도 검증 환경이 마련되기 전까지 피한다. 합성 이벤트, 모의 HTTP/모델, 임시 SQLite로 검증한다. `.env`, 키, 내부 데이터는 Git에 넣지 않는다.
- 현재 `x-eventprobe-user`/쿠키 작업공간 ID는 **자가 선언 구분값**이다. 사내 다중 사용자 인증 경계로 간주하지 않는다. 네트워크 공개 전 인증과 권한 검사가 필요하다.

## 병렬 작업 규칙

- 클로드가 완료한 N1(`7d29cd4`), N5(`13d65be`)와 Codex의 N6(`d39b684`), N7(`95364ff`, `6fc77d9`)을 중복 구현하지 않는다. 다음 담당 항목은 작업 시작 시 문서/메시지로 표시한다.
- `backend/core/agent.py`, `backend/core/agent_store.py`, `backend/routers/agent.py`, `frontend/static/js/agent.js`, `frontend/static/js/workspace.js`, `frontend/templates/index.html`은 공유 접점이다. 동시 직접 편집 대신 각자 worktree에서 좁은 기능 커밋을 만들고 최신 브랜치에 합친 뒤 전체 회귀 테스트를 실행한다. 타인의 미커밋 변경은 되돌리지 않는다.
- 보관/삭제/재개/대상 요청/AI 반출은 별도 계약 테스트를 둔다. 조회 UI는 대상·AI 호출 0회를 확인한다.

## 다른 PC에서 시작

1. `git clone -b harden/access-guard-scoring-tests https://github.com/leesihyeon1/EventProbe.git` 후 `cd EventProbe`. 이미 clone했다면 `git fetch origin` 뒤 이 브랜치로 전환하고 최신 커밋을 fast-forward한다. 작업 중 변경이 있으면 먼저 보존하고 강제 reset하지 않는다.
2. Windows PowerShell 기준 `py -3.11 -m venv .venv`, `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`. Node.js도 프런트엔드 테스트에 필요하다. `.env`와 `backend/data/agent/runs.sqlite3`는 Git으로 옮기지 않는다. 운영 데이터 이전이 필요하면 별도 승인된 암호화 경로와 복원 검증을 사용한다.
3. `.\.venv\Scripts\python.exe -m pytest backend/tests -q`, `node --test frontend/tests/*.test.js`, `.\.venv\Scripts\python.exe -m pytest docs/reviews/2026-10-13/review_contract_checks.py -q`를 실행한다. 마지막 N7 격리 브랜치에서는 백엔드 1008개, 프런트엔드 82개, 계약 검사 통과. 원격 브랜치에서 다시 검증한다.
4. 위 우선순위의 한 묶음을 담당하고 합성 데이터로 구현·테스트한 뒤 커밋한다. 실제 사내 대상/모델 연결은 별도 승인 단계로 남긴다.

관련 진입점: `backend/core/agent.py`, `backend/core/agent_store.py`, `backend/routers/agent.py`, `backend/routers/agent_history.py`, `frontend/static/js/agent.js`, `frontend/static/js/workspace.js`, `frontend/static/js/agent_history.js`, `frontend/templates/index.html`. 실행 방법과 접근 토큰 설정은 루트 `README.md`를 따른다.
