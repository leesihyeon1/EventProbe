# EventProbe RAG 구현 및 운영 설계

> 상태: 구현됨. 대상 환경은 로컬 FastAPI와 공용 PC이며, 별도 벡터 DB 없이 JSON 원문과
> NumPy 벡터 행렬을 사용한다.

## 목적과 경계

RAG는 탐지 결과를 결정하지 않는다. 결정적 분석 엔진이 만든 판정은 그대로 유지하고,
다음 생성 작업에 외부 보안 문서의 근거를 제공한다.

- 요청에 맞는 테스트 페이로드와 WAF 우회 변형 생성
- 확인된 공격 신호의 영향·재검증 방법·조치 설명
- 리포트의 공격 유형별 참고 자료 제시

## 파이프라인

```text
URL·PDF·Markdown·텍스트
  → 본문 추출 및 구조 인식 청킹(900자, 120자 겹침)
  → JSON 청크 저장
  → passage 임베딩 및 .npy 저장
  → 요청별 query 구성
  → BM25 top-k + 벡터 top-k
  → Reciprocal Rank Fusion
  → 카테고리 부스트, 중복 제거, 소스당 최대 2개
  → 관련 청크를 생성 프롬프트에 주입
  → 결과에 출처·위치·발췌 표시
```

벡터 DB 제품은 사용하지 않는다. 현재 코퍼스 규모에서는 정규화한 NumPy 행렬과 내적을
이용한 완전 검색이 단순하고 충분하다. 데이터가 수십만 청크 이상으로 증가하거나 다중 프로세스
동시 쓰기가 필요해지면 FAISS, Qdrant, pgvector 같은 저장소를 검토한다.

## 인덱스 일관성

각 소스에는 다음 임베딩 메타데이터가 저장된다.

- 임베딩 모델
- 벡터 차원
- 청커 버전
- 청크 내용 SHA-256
- 임베딩 생성 시각

모델·본문·청커 버전·벡터 형태가 현재 설정과 다르면 해당 벡터는 검색에서 제외하고 BM25로
계속 동작한다. 관리 UI에서 `재색인 필요`로 표시하며, **임베딩 갱신**으로 다시 생성한다.
새로 인제스트한 소스는 JSON에 메타데이터를 저장한다. 저장소에 포함된 기존 벡터는
`embedding_manifest.json`으로 같은 정보를 관리해 불필요한 재임베딩을 피한다.

## 임베딩 설정

`EMBEDDING_*`를 지정하면 빠진 값은 `AI_* → NVIDIA_*` 순서로 보완한다. 임베딩 설정을
명시하지 않으면 기존 `NVIDIA_*`만 사용한다. 채팅 전용 OpenAI 호환 서버를 임베딩 서버로
오인하지 않기 위한 구분이다. 권장 설정은 다음과 같다.

```env
EMBEDDING_API_KEY=...
EMBEDDING_BASE_URL=https://provider.example/v1
EMBEDDING_MODEL=embedding-model-id
```

임베딩 API가 없거나 실패하면 BM25 검색을 사용한다. 유효한 벡터가 있으면 BM25와 벡터를
결합한 `hybrid` 모드로 동작한다. 현재 모드는 RAG 관리 UI와 `/api/rag/sources`에서 확인한다.

## 용도별 질의

공통 질의 빌더는 값보다 구조를 사용한다.

- HTTP 메서드와 호스트를 제외한 경로
- URL·요청 파라미터 이름
- JSON 중첩 키, 폼 필드명, XML 태그명
- 민감 헤더를 제외한 헤더 이름
- 공격 카테고리, 서버·프레임워크 지문
- 판정 보강 시 finding 이름과 비밀값을 제거한 근거 핵심어

긴 토큰·JWT·키처럼 보이는 값은 질의에서 제거한다. 질의 자체는 로컬 검색에만 사용한다.

## 검색과 재정렬

BM25는 CVE·경로·함수·헤더 같은 정확한 문자열에 강하고, 벡터 검색은 자연어로 표현된 원리와
조치 검색에 강하다. 두 후보 목록을 RRF로 결합한 후 공격 카테고리 용어를 소폭 가산한다.
동일 청크는 제거하고 하나의 대형 문서가 결과를 독점하지 않도록 소스당 최대 2개만 선택한다.

검색 점수는 0~1 범위로 정규화된다. 호출 목적에 따라 관련도 하한을 적용하고, 낮은 점수만
나오면 문서를 억지로 주입하지 않는다.

## 생성 프롬프트의 근거 사용

검색 청크는 `RAG_REF_1`, `RAG_REF_2`처럼 번호가 붙은 비신뢰 참고자료로 전달한다.
모든 생성 프롬프트는 문서 안의 지시·역할 변경·출력 형식 요구를 무시하고, 현재 요청의
제품·경로·파라미터·공격 유형과 직접 맞는 기술 사실만 사용하도록 규정한다.

- 페이로드 제안은 관찰된 요청 구조를 가장 먼저 따르고, 실제 사용한 근거 번호만 `rag_ref`에 기록한다.
- WAF 변형은 기본 payload의 공격 의미를 유지하는 변환 기법만 참고한다.
- 종합 판정은 RAG로 outcome·severity·confidence를 바꾸지 않고 priority·remediation만 구체화한다.
- 종합 판정의 `rag_refs_used`에는 실제 반영한 번호만 남겨 검색 개수와 사용 개수를 구분한다.

## 데이터 전송과 개인정보

색인과 검색은 로컬에서 수행한다. AI 기능이 켜져 있으면 검색된 문서 발췌가 AI 제공자의
프롬프트에 포함된다. 따라서 내부 문서를 넣을 때는 로컬 AI 엔드포인트 사용을 권장한다.

요청 컨텍스트에서는 Host, Cookie, Authorization, API 키 및 CSRF 토큰 헤더를 제거한다.
하지만 문서 본문, URL 경로, 요청 본문, 탐지 evidence 안의 모든 민감정보를 자동으로 보장해
익명화하는 것은 아니다. 클라우드 AI를 사용할 때는 인제스트 자료와 전송 범위를 확인한다.

## 품질 평가

골든셋은 `backend/data/rag_golden.json`에 있으며 보안 주제 25개와 허용 가능한 근거 소스를
정의한다. 다음 명령은 실제 코퍼스에서 Recall@k와 MRR을 계산하며 기준 미달이면 실패한다.

```bash
python backend/tools/evaluate_rag.py
```

2026-09-21 BM25 기준 결과는 Recall@5 1.0, MRR 0.8813이다. 임베딩 모델이나 코퍼스,
청킹·재정렬 로직을 바꿀 때 같은 평가를 다시 실행한다. 생성 품질은 별도로 요청에 없는
파라미터 생성률, `rag_ref` 출처 정확도, 후보 중복률을 관찰한다.

## 관리 API

- `POST /api/rag/ingest`: URL 또는 파일 인제스트
- `GET /api/rag/sources`: 소스, 검색 모드, 모델, 최신·재색인 필요 상태
- `POST /api/rag/reindex`: 없거나 오래된 임베딩 갱신
- `DELETE /api/rag/sources/{source_id}`: 소스와 벡터 삭제
- `POST /api/rag/report-refs`: 리포트용 관련 자료 검색
