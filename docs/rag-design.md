# EventProbe RAG 설계 (AI 페이로드 생성 품질 보완)

> 상태: **설계안(미구현)**. 리뷰용. 대상 환경 = 경량 FastAPI + 공용 PC(무거운 모델/DB 지양).

## 1. 문제 정의

- **AI 페이로드 생성**(`ai_suggest_payloads`)이 정적 PAYLOAD BANK 예시만 보고 생성 → 환각(존재하지 않는 파라미터), 일반적/산발적 페이로드.
- 이미 검색 로직은 있음: `cve_matcher`(지문/경로 → CVE), `followup`(신호 → 승격). **그러나 검색 결과를 LLM 프롬프트에 넣지 않고** 결과 리스트에서 합치기만 함.
- **핵심 갭 = 검색(retrieval)한 실제 지식을 생성기(LLM)에 주입하지 않음.** ← RAG로 메울 지점.

### 범위 (무엇에 효과 있나)
| 대상 | RAG 적합성 | 처방 |
|---|---|---|
| AI 페이로드 생성 | 높음 | **RAG(검색-그라운딩 생성)** |
| 탐지 정확도(analyzer) | 낮음 | 결정적 시그니처 + 확증 스캔(RAG 아님) |
| 분석 서술/조치(remediation) | 중간 | 취약점별 지식 검색 주입(선택) |

> 결론: **RAG는 "생성"에 적용**하고, "탐지"는 지금처럼 결정적 엔진으로 간다.

## 2. 목표

1. 생성 페이로드가 **대상 엔드포인트/파라미터/기술스택/지문에 근거**하도록(환각↓, 구체성↑).
2. 새 무거운 의존성 없이(1단계) 대부분의 향상 확보.
3. 무유출 원칙 유지: 검색은 **로컬 코퍼스**에서, LLM 에는 기존과 동일하게 요청 라벨/경로/파라미터명만 전송(응답 본문·호스트·인증 제외).

## 3. 아키텍처 (단계적)

### 1단계 — 로컬 뱅크 RAG-lite (권장, 경량)
```
요청(method·path·params·body 키·헤더명)
        │
        ▼
[쿼리 빌더] endpoint 세그먼트 + 파라미터명 + 기술스택(detect_stack) + 지문(server/powered_by)
        │
        ▼
[BM25 검색기]  ← 코퍼스: payloads.json(카테고리 595 + CVE 823) 색인
        │  top-k(예: 8) 관련 실제 페이로드 + 메타(카테고리·CVE·설명)
        ▼
[프롬프트 주입]  system 정적 BANK 대신/추가로 "RETRIEVED(실제, 이 대상에 적합)" 블록
        │
        ▼
LLM(NVIDIA NIM) → 후보 생성(검색된 것 우선 적용/변형)
        │
        ▼
[후처리] 기존 정규화/중복제거/카테고리 캡 + 출처표기(retrieved/ai)
```
- **의존성**: 순수 파이썬 BM25(직접 구현 ~50줄) 또는 `rank-bm25`(경량, 선택). 벡터/임베딩 없음.
- **색인**: payloads.json 로드 시 각 항목을 `name+description+payload+category+applies_to` 텍스트로 토큰화해 인메모리 색인(mtime 변경 시 재색인 — load_payloads 패턴 재사용).
- **쿼리**: 경로 세그먼트(`/GponForm/diag_Form`→`gponform diag_form`) + 파라미터명 + 기술스택 라벨 + 지문. 불용 세그먼트(api/v1/static…) 제거.

### 2단계 — 임베딩 벡터 RAG (선택, 무거움)
- 코퍼스 확장: PayloadsAllTheThings, Nuclei matcher, 기법/조치 노트.
- 임베딩(`sentence-transformers`, 예: `all-MiniLM-L6-v2`) + 로컬 벡터스토어(`chromadb`/`faiss`).
- 의미 검색으로 커버리지↑. 단 의존성·인덱싱·모델 로딩 부담(공용 PC 부적합할 수 있음).
- **1단계로 부족할 때만** 진입. BM25가 큐레이션 뱅크엔 종종 충분.

## 4. 프롬프트 주입 형식 (1단계)

```
[TARGET]
method: POST
path: /GponForm/diag_Form?images/
params: {}
body_keys: [dest_host, diag_action, ...]
tech: Apache, (framework)

[RETRIEVED — 이 대상에 적합한 실제 페이로드(이걸 우선 적용/변형)]
1) (cve CVE-2018-10562) GPON dest_host 명령주입 — POST body dest_host=;id;  [why: ...]
2) (cmdi) ;id / $(id) / `id`  [why: OS 명령 주입]
...

규칙: 위 RETRIEVED 를 최우선으로 이 요청에 맞게 구체화하라. 목록에 없는 파라미터를
지어내지 말 것. 최대 N개, 카테고리당 3개.
```
- 검색 결과가 강하면 그대로 후보로도 노출(출처 `retrieved`), LLM 은 변형/보강만.
- 무유출: RETRIEVED 는 로컬 데이터, TARGET 은 기존과 동일(호스트/인증/응답 제외).

## 5. 평가 (품질 회귀 방지)

- **골든셋**: 대표 엔드포인트 20~30개(GPON, /manager, /.env, /actuator, login, ?id= 등) → 기대 카테고리/CVE 라벨.
- **지표**: (a) 기대 카테고리 상위 노출률 (b) 환각 파라미터율(요청에 없는 param) (c) 중복률.
- RAG on/off A/B 로 (a)↑ (b)↓ 확인. `pytest` 로 검색기(순수 함수) 단위 테스트 + 골든셋 스냅샷.

## 6. 리스크 / 결정

- BM25 쿼리 과대 매칭 → top-k 제한 + 점수 임계.
- 코퍼스 편중(CVE 823 vs 카테고리 595) → 카테고리 균형 샘플링.
- LLM 이 RETRIEVED 무시 → 프롬프트에 "최우선 적용" 강제 + 후처리에서 retrieved 우선 배치.
- 무유출 불변식 유지(검색=로컬, 전송=라벨-only).

## 6.5 문서 인제스트 (URL / PDF → RAG DB)  ← 사용자 요청

사용자가 **링크나 PDF/문서**를 주면 코퍼스에 넣어 검색 대상으로 만든다. 페이로드 뱅크와
**같은 검색 계층**에 합류(BM25 1단계 / 벡터 2단계).

### 파이프라인
```
입력(URL | PDF | .md/.txt)
   │  ┌ URL  : httpx fetch → HTML 본문 추출(readability/간이 스트리퍼)
   ├──┤ PDF  : 텍스트 추출(pypdf/pdfplumber)  ※ pdf 스킬 재사용 가능
   │  └ 텍스트: 그대로
   ▼
[정제] 보일러플레이트 제거 → [청킹] ~800자 + 겹침 100자, 출처(url/파일·페이지) 메타 부착
   ▼
[색인] 1단계 BM25 인메모리/디스크 / 2단계 임베딩→벡터스토어
   ▼
[영속화] data/rag/ 에 원문청크+인덱스 저장(재시작 후에도 유지 = 'RAG DB')
   ▼
생성 시 [뱅크 + 문서] 통합 검색 → top-k 주입
```

### 의존성 (1단계 기준)
- URL: `httpx`(기존) + HTML→텍스트(`beautifulsoup4` 또는 간이 정규식 스트리퍼).
- PDF: `pypdf`(경량) 또는 `pdfplumber`(표까지, 무거움). 선택 의존성으로.
- 색인/검색: 순수 파이썬 BM25(의존성 0). 2단계만 임베딩 필요.

### 어떤 문서가 효과적인가
- **API 문서/스웨거**: 대상의 **실제 파라미터·엔드포인트**를 학습 → '파라미터 환각' 문제를 직접 해소(가장 가치 큼).
- 취약점 어드바이저리·익스플로잇 라이트업·PayloadsAllTheThings 페이지: 실제 페이로드/기법.
- 노이즈 문서는 품질을 떨어뜨리므로, 소스별 on/off·삭제 관리 UI 필요.

### ⚠️ 무유출(중요)
- **검색·색인·저장은 전부 로컬** → 여기까지는 유출 없음.
- 그러나 검색된 **문서 청크를 클라우드 LLM(NVIDIA) 프롬프트에 주입**하면 그 내용이 외부로 나간다.
  → 다음 중 하나로 처리:
  1) 문서-RAG 사용 시 **로컬 NIM(NVIDIA_BASE_URL)** 권장,
  2) 클라우드면 "주입 청크가 AI 로 전송됨" **경고 + opt-in 토글**(AI_RESPONSE_ANALYSIS 와 동일 정책),
  3) 민감 문서는 **로컬 검색 결과만 후보로 노출**(LLM 주입 없이).
- 인제스트한 문서에 시크릿이 들어있을 수 있으므로 저장 위치(data/rag/)는 .gitignore.

### 관리 UI/엔드포인트(초안)
- `POST /rag/ingest` {url | (파일 업로드)} → 청킹·색인·저장, 소스 id 반환.
- `GET /rag/sources` 목록 / `DELETE /rag/sources/{id}` 삭제.
- 생성 시 소스 필터(어떤 문서를 검색에 쓸지 선택).

## 7. 제안 진행 순서

1. (이 문서) 설계 합의.
2. 1단계: BM25 검색기(순수 파이썬) + 색인 + 프롬프트 주입 + 골든셋 평가. **의존성 0, 되돌리기 쉬움.**
3. 측정 후 부족하면 2단계(임베딩) 검토.
