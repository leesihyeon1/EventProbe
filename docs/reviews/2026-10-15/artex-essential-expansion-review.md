# 기존 계획 밖 ARTEX 기능과 필수 적용 범위 검토

> 병렬 작업 조정(2026-10-15): Codex는 **N6 선택 발견 증거 패키지 ZIP**을 별도 worktree `finding-evidence-export`에서 담당한다. Claude는 N6 구현을 중복 시작하지 말고 다른 항목을 진행한다. 공용 라우터/화면 연결은 Codex의 독립 구현 검증 후 합칠 때 조정한다.

검토일: 2026-10-15. EventProbe `ec98953`, 검토 시작 시 작업 트리 clean. 참조는 `D:\ARTEX-main\ARTEX-main`의 로컬 소스다. 이번에는 소스와 계획서를 대조했고 실제 내부 대상, 운영 DB, NVIDIA API는 사용하지 않았다. 테스트/브라우저 실행으로 최신 기능의 완성도를 입증한 검토는 아니다.

## 결론

클로드 작업으로 발견 관리, 로컬 HTML 보고서, 커버리지 표, 발견별 재검증, 승인 계획 고정, 반출 감사 화면, 삭제 감사, 작업공간 구분, 불명확한 쓰기 재개 차단이 추가됐다. 이를 미구현으로 다시 제안하면 안 된다.

다만 기존 계획은 ARTEX 전체 기능 명세가 아니다. 작업 템플릿/분류, 여러 목표와 지속 제약, 작업 간 근거 계승, 실행 중 개입, 아카이브 복원, 증거 패키지, 이벤트 트리거가 빠졌거나 운영 수준의 완료 조건이 부족하다. 현재 계획의 완료와 필수 기능 전체 완료는 서로 다르다.

여기서 **필수**는 사용자의 사내 이벤트 검증, 외부 응답 비반출, 장시간 자율 작업의 완결성, 반복 검증과 증거 추적에 필요한 기능을 뜻한다. ARTEX의 모든 버튼이나 실행 권한을 그대로 가져온다는 의미는 아니다. 아래의 필수 범위 전체를 차기 작업 범위에 포함하는 것을 권장한다.

## 4. 적용 가능하지만 공통 필수로 보지 않는 기능

- 여러 AI worker: 동시 처리 병목이 확인되면 제한된 로컬 worker부터. 단일 계획기로도 필수 검증 흐름 구현 가능.
- 범용 shell, 임의 도구 설치, 외부 MCP: 승인된 검증 도구를 등록하는 방식 우선. 사내 목적에 필요한 도구가 있을 때 개별 적용.
- 범용 MITM 프록시: 브라우저/외부 도구의 트래픽 수집이 필요할 때 도입. 현재 HTTP 실행 기록의 통합부터 완료.
- 자동 스파이더/DNS 보강: URL 자동 발견이 업무 범위에 필요하면 추가. 단일 이벤트 확인에도 반드시 필요한 기능은 아님. 시작 승인과 깊이/요청/시간 제한 필요.
- 원문 기반 외부 AI 채팅/기억/보고서/질의: 현재 비반출 조건과 충돌. 로컬 규칙/검색/보고서 또는 사내 추론으로 대체.
- 특정 외부 자산 제품, 외부 메신저, Go 단일 바이너리 업데이트: 사내 운영 환경에 맞는 연결/배포 방식으로 대체.

## 5. 권장 구현 묶음

1. **실행 완결성:** 체크포인트, 목표별 완료 조건, 로컬 제약 정책, 승인 수명, 실행 중 개입, 인증 경계(협업 시). 기존 재개 안전장치 보존.
2. **반복 검증 업무:** 템플릿/분류, 사건 ID, 공통 자산·트래픽·발견 연결, 작업 간 근거 계승, 접근 제어 포함 재검증/비교.
3. **증거 운영:** 전체 기록 검색/페이지 조회, 증분 이벤트/큰 본문 조회, 선택 증거 패키지, 보관/복원, UI 흐름 통일.
4. **무인 운영:** 실제 설정/도구 실행 계측, 내부 알림, 정기·이벤트 트리거, 중복 실행 방지. 그 후 필요한 worker/MCP/스파이더 연동.

각 묶음 완료는 UI 존재가 아니라 **API·저장·실행/권한·증거 연결·오류/재시작 처리·합성 통합 테스트·브라우저 동작**을 기준으로 판단한다. 로컬 전용 조회/보고서/내보내기에서 AI 또는 대상 요청이 발생하지 않는지도 검증한다.

## 검토 범위와 산출물

기존 작업계획은 유지하고 이 문서를 추가 요구사항과 수용 기준으로 사용한다. 참조 파일은 제공된 ARTEX 소스이며 최신 원격판이나 모든 플러그인을 전수 확인한 것은 아니다. 이번에 제품 코드를 수정하거나 테스트를 실행하지 않았다. 기존 테스트 수를 최신 변경의 통과 결과로 재사용하지 않는다.

검토 종료 직전 다른 작업에서 `ai_analyzer.py`, `ai_egress.py`, `rag.py`, `routers/api.py`, 관련 테스트 및 감사 UI 파일이 변경되기 시작했다. N10 사용량/지연 계측의 현재 구현 상태는 해당 작업 완료 후 재확인해야 하며 중복 구현하지 않는다. 이 변경은 본 검토의 코드 확인 기준 이후라 완성도를 평가하지 않았다. 문서 범위 `git diff --check`는 통과했으며 전체 diff 검사는 동시 변경된 `routers/api.py`의 공백 경고를 보고했다. 다른 작업의 코드는 수정하지 않았다.
