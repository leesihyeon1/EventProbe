# 자율 검증 조기 종료와 결론 누락 개선

## 확인된 원인

최근 로컬 실행 4건의 상태, 카운터, 고정된 중단 사유 코드만 조회했다. 대상 URL, 목표, 응답 본문은 진단 출력에 포함하지 않았다.

- 3건: 이전 행동과 같은 행동을 모델이 한 번 선택하면 `completed`로 즉시 종료했다. 한 건은 정상 응답 1회만 관측한 상태였다.
- 1건: HTTP 요청 24회 한도에서 종료했다.
- 예산/오류/중단 경로에 공통 결론 생성 단계가 없어 사용자가 종료 이유와 검증 결과를 따로 추적해야 했다.
- 일반 probe의 3회 요청 비용을 사전 확인하지 않아 요청 일부만 보낸 뒤 예산이 소진될 수 있었다.

## ARTEX와 비교

제공된 ARTEX 소스의 [plannerLoop](D:/ARTEX-main/ARTEX-main/server/engine.go:800)는 계획 라운드와 작업 상태를 관리하며, [worker 실행](D:/ARTEX-main/ARTEX-main/server/engine.go:1030)은 재시도 정책을 별도로 적용한다. [settleTask](D:/ARTEX-main/ARTEX-main/server/engine_timeout.go:184)는 시간 제한 도달 시 정리와 최종 상태 확정을 일반 실행과 구분한다.

EventProbe에는 이 중 **제한된 복구, 실행 전 비용 확인, 공통 종료 정리**를 적용했다. ARTEX의 전체 다중 에이전트 엔진을 복사하거나 외부 모델에 내부 증거를 보내는 종료 추론은 도입하지 않았다.

## 변경 내용

1. 반복 행동, 근거 누락, 모델 출력 형식 오류에는 기존 AI/시간 예산 안에서 최대 3회의 행동 선택 기회를 둔다. 거절된 행동을 HTTP로 실행하지 않고 고정 코드로 수정 사유를 알려준다.
2. AI 제공자 연결 오류와 일부 일시 HTTP 오류만 제한적으로 재시도한다. 인증 실패, 반출 가드 실패, 다른 실행의 증거 참조는 자동 우회하지 않는다. 대상 HTTP 요청의 불명확한 결과를 자동 재전송하지 않는다.
3. probe/access는 3회, confirm은 baseline과 두 회차의 실제 프로브 수를 합산해 사전 비용을 확인한다. 더 적은 예산으로 가능한 행동을 선택하거나 부분 결과로 종료한다. 사용자 지정 예산을 자동 증가시키지 않는다.
4. 모든 정상/제한/중단/오류 종료에 로컬 `conclusion`을 저장한다. 확증, 의심, 미확정, 관측 수, 판정되지 않은 검사, 증거 ID, 중단 사유, 다음 조치를 구별한다. 모델의 종료 문장을 취약성 판정 근거로 사용하지 않는다.
5. 기존 기록을 조회할 때도 로컬 결론을 계산한다. 응답 본문을 읽거나 외부 AI를 호출할 필요가 없다. 이전 버전의 반복 종료는 부분 결론으로 표시한다.
6. 상세 화면 상단에 결론을 표시하고 검사별 근거 보기 버튼으로 실제 verification 이벤트로 이동한다. 함께 반영된 탐색 그래프는 유지한다.
7. 계획 모드에서도 순회 한도, 반복 분기, 후속 분기 없음과 명시적인 종료 분기를 구분하고 부분 결론을 남긴다.

## 보안 및 범위

- 결론 생성은 순수 로컬 집계이며 외부 모델 호출을 추가하지 않는다. 응답 본문/헤더를 새 결론 입력으로 전송하지 않는다.
- 반복 모드의 기존 상태코드/탐지 요약 피드백 정책은 변경하지 않았다. 응답 유래 정보 전체의 비반출이 요구되면 별도로 응답-블라인드 계획 모드를 기본 정책으로 확정해야 한다.
- 계속 진행할 근거나 예산이 없는데도 무한히 실행하거나, 미확정을 안전으로 바꾸지 않는다.
- 계획 모드의 중단 지점 체크포인트 재개, 예산 증액을 통한 동일 실행 연장, 전체 자산 커버리지 및 업무용 보고서는 이번 수정 범위가 아니다.
- 기존 서버는 `python main.py`로 실행 중이며 자동 반영이 꺼진 상태다. 수정 적용에는 해당 서버 재시작이 필요하다. 진단 시점에 실행 중 작업은 0건이었다.
