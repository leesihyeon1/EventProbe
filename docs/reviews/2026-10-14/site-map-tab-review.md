# 작업별 사이트맵 탭 검토

## 판단

**작업 상세에 `사이트맵`을 별도 탭으로 두는 것이 적절하다.** 기존 탐색 그래프는 행동과 증거의 관계이고, 사이트맵은 대상 URL의 구조와 관측/검증 상태이므로 서로 대체할 수 없다. 다만 "그림을 보여주는 기능"과 "추가 URL을 요청하는 스파이더"는 분리해야 한다.

이번 요청은 검토이므로 사이트맵이나 크롤러를 새로 구현/실행하지 않았다.

## 권장 화면

작업 상세: `개요/결론 | 실행 기록 | 탐색 그래프 | 사이트맵`

사이트맵 내부 보기: `트리 | 목록 | 관계도`. 초기 버전은 트리와 목록을 우선하고, 복잡한 자산 관계도가 필요할 때 그래프를 추가한다. 수백 개 URL을 한 번에 force-directed 그래프로 배치하는 것보다 트리/표가 경로 검색과 반복 업무에 적합하다는 설계 판단이다.

- 왼쪽: origin(스킴/호스트/포트) -> 경로 세그먼트 -> 메서드별 엔드포인트 트리. 검색/접기/펼치기 제공.
- 가운데: 선택 경로의 메서드, 마지막 상태코드, 콘텐츠 유형, 발견 출처, 관측 시각, 검사 상태. 상태는 계정별 차이를 보존한다.
- 오른쪽 또는 하단 상세: 연결된 요청/응답 증거, 해당 경로를 사용한 행동, 검증 판정으로 이동. 증거는 로컬 텍스트로 표시한다.
- 상태: `발견만 됨`, `요청함`, `판정 있음`, `확증`, `접근 실패`, `범위 밖`을 구별한다. 200 응답이나 URL 발견만으로 "검증 완료/안전"을 표시하지 않는다.
- `/api` 같은 경로 그룹 노드는 실제 요청한 URL이 아닐 수 있으므로 그룹과 실제 엔드포인트를 구별한다.
- 사이트맵의 URL 계층과 탐색 그래프의 증거 인과관계를 섞지 않는다. 서로의 상세로 이동할 수 있게 연결한다.

## 데이터 및 안전 설계

1. 초기 탭은 이미 저장된 데이터만 읽는다. 탭 열기, 노드 펼치기, 그래프 확대가 새 대상 요청이나 AI 호출을 유발하지 않게 한다.
2. URL 값과 인증 정보가 들어간 쿼리는 기본 목록에서 숨기고 로컬 상세로만 제공한다. 원본 URL은 보존하되 표시/그룹용 키를 별도로 만든다.
3. 그룹 키는 origin, HTTP 메서드, 경로, 쿼리 키 집합 등을 사용한다. 실제 객체 ID나 쿼리 값이 다른 요청의 증거를 덮어쓰지 않는다. 공격 페이로드 변형마다 새 사이트 구조 노드를 만들지 않는다.
4. 발견 URL마다 `source_observation_id`, 원본/그룹 ID, 실제 요청 여부를 기록한다. 문자열 경로의 부모 관계를 실제 링크 클릭 관계로 오인하지 않는다.
5. 원본 도메인/URL/응답은 로컬 저장 및 로컬 렌더링만 사용한다. 원격 다이어그램 렌더러, 외부 AI 요약, CDN/telemetry를 붙이지 않는다.
6. 능동 스파이더는 별도 시작 명령과 허용 범위/깊이/URL 수/요청 수/시간/동시성 제한이 필요하다. 탭 표시 기능과 별도로 승인하고, 기존 실행의 총 요청 예산도 지킨다.
7. 같은 루트 도메인의 다른 하위 도메인을 자동 허용하지 않는다. 스킴/호스트/포트와 명시적 범위를 확인한다. 리다이렉트 목적지와 계정 세션도 범위 검사를 통과해야 한다.
8. GET도 부작용이 있을 수 있으므로 로그아웃/변경 동작 경로를 무조건 방문하지 않는다. 읽기 전용으로 승인된 경로 범위를 우선한다.
9. 초기에는 "현재 작업에서 관측한 URL N개"만 표시한다. 전체 자산 목록과 검사 범위의 분모가 확정되기 전에는 전체 도메인 커버리지 백분율을 만들지 않는다.

## 적용 순서

1. 수동/자율 검증에서 이미 관측한 URL의 사이트맵 탭.
2. 발견 출처와 증거 연결, 계정/메서드별 검사 상태.
3. 사용자가 명시적으로 시작하는 제한된 스파이더.
4. 필요할 때 여러 작업을 합친 자산 목록과 커버리지.

Python/FastAPI와 현재 로컬 프런트엔드를 유지해 구현 가능하다. NVIDIA에 도메인이나 응답을 보내거나 Go로 재작성할 이유는 없다.

## 1차 구현 결과

- 작업 상세의 `타임라인 | 탐색 그래프 | 사이트맵`에 별도 탭 추가. 결론은 기존 상단 영역을 유지한다.
- 사이트맵은 현재 자율 검증 작업의 저장된 엔드포인트/이벤트만 사용한다. 트리와 목록, 경로 검색, 메서드/검사 상태 필터, 경로 상세와 증거 이벤트 이동을 제공한다.
- origin + 메서드 + 경로 + 쿼리 키 집합으로 그룹화한다. 쿼리 값, 요청 헤더/본문, 응답 본문은 사이트맵 모델에 복사하지 않는다. 원본 증거는 기존 로컬 타임라인에서 확인한다.
- probe/confirm의 공격 입력 변형은 실제 실행 단계가 가리키는 원래 엔드포인트에 연결한다. 다른 origin의 관측을 시작 요청으로 합치지 않는다.
- 발견/미요청, 요청/응답 없음, 관측/미판정, 확증/의심/미확정 및 요청 오류를 구분한다. 유효한 관측 참조가 일부 누락된 판정은 확증으로 표시하지 않는다.
- 행위자별 최근 HTTP 상태와 해당 행위자의 판정을 분리한다. 접근 제어 검사의 소유자 baseline에는 검사 대상 행위자의 확증을 전파하지 않는다.
- 새 발견에 `discovery` 이벤트와 `source_observation_id`를 기록하며, 40개 엔드포인트 한도에 걸린 경우 `discovery_limit`를 남긴다. 기존 링크 추출 범위와 요청 예산은 바꾸지 않았다.
- 기존 기록에 발견 출처가 없으면 `출처 미기록`으로 표시한다. 기존 실행에 대한 출처를 추정하거나 소급 생성하지 않는다.
- 폴링 중 동일한 사이트맵은 다시 그리지 않는다. 검색/필터/선택/트리 펼침 상태를 유지하며 작업 변경 시 초기화한다. 탭 키보드 이동, 모바일 배치, 밝은/어두운 테마를 지원한다.

### 안전 및 제한

- 이 탭 자체에는 대상 HTTP 요청, AI 호출, 원격 렌더러, CDN, 텔레메트리 호출이 없다. 기존 작업 조회 API의 로컬 스냅샷을 사용한다. 기존 엔진의 AI 반출 정책 자체를 변경한 작업은 아니다.
- 능동 스파이더, 수동 요청/분석 이력의 통합, 여러 작업의 자산 통합, SPA/OpenAPI 전체 경로 수집, 관계도 보기는 이번 범위에 포함하지 않는다.
- 전체 도메인 검사율이나 안전 판정은 제공하지 않는다. 표시 수는 현재 작업에 기록된 그룹 수다.
- 콘텐츠 유형 등 추가 응답 메타데이터는 원본 증거에서 확인한다. 초기 사이트맵 상세에는 행위자별 HTTP 상태와 관측 시각을 우선 제공한다.
- 프런트엔드 탭은 브라우저 새로고침으로 적용된다. 새 발견 근거 이벤트는 백엔드 재시작 이후 실행부터 기록된다. 기존 사용자 서버는 임의로 종료하지 않았다.
