# 탐색-계획-검증 순환 구현

## 실행 흐름

기본 반복 모드에서 시작 요청을 관측하고, 같은 출처의 HTML 링크 및 GET/POST 폼을 로컬 엔드포인트 목록에 등록한다. 작업 단계와 HTTP 한도에서 검사 몫을 남기며 최대 3개의 추가 GET 경로를 관측한다. 응답 헤더의 기술 스택은 기존 정적 서명으로 분류한다. 원본 서버 헤더는 로컬 사이트맵용으로만 보존한다.

탐색 이후 외부 AI가 호출될 때 입력은 별도로 생성한 구조화된 객체다. 대상 호스트, 자유 목표 문장, 응답 본문, 서버 헤더 값, 이전 페이로드와 가설은 포함하지 않는다. 전달 항목은 경로 템플릿, 입력 필드 이름, 정적 기술 이름, 상태 코드, 검사 상태와 잔여 예산이다. AI는 한 번에 하나의 후속 행동과 페이로드를 고른다. 실제 요청 범위와 예산은 로컬에서 다시 검사한다.

probe가 의심 판정이면 같은 엔드포인트·필드·계정에 대해 반복 대조 검사를 우선한다. SQL 입력은 문자열/숫자 프로필로 요청 수를 제한한다. 두 회차 결과와 증거 ID를 연결한 후 다음 AI 계획으로 돌아간다. 요청 예산이 모자라면 반복 검사를 시작하지 않고 부분 결론을 남긴다. 종료 시 결론은 증거가 연결된 확인·의심·미확정 상태를 구분한다.

## ARTEX와의 관계

ARTEX `agent/planner.go`는 자산·사실·발견 변화에 따라 intent를 다시 만들고, `agent/worker.go`는 한 intent의 관측을 기록한다. EventProbe는 기존 Python 실행기를 유지하고 이 피드백 원칙을 작은 HTTP 작업 루프에 적용한다. ARTEX의 셸 중심 실행이나 원문을 외부 모델에 전달하는 방식은 사용하지 않는다.

## 검증 범위

- 합성 사이트의 루트에서 여러 링크를 발견하고 3개 GET까지만 먼저 관측한다.
- 관측한 nginx 헤더는 로컬 요약에 남고 AI 요청에는 정적 기술 이름만 포함된다.
- AI가 선택한 XSS probe의 의심 신호는 로컬 confirm으로 재검증한 후 다시 AI에 상태 요약을 전달한다.
- 모델 호출 직전 직렬화에서 응답, 도메인, 서버 헤더 값, 이전 페이로드가 제거되는지 확인한다.
- 기존 사이트맵 경량 API와 별도 폼/SQL 검증 경로를 회귀 검사한다.
- 전체 백엔드 1,125개, 프런트엔드 136개 테스트 통과. 외부 AI 전송 경계 보강 후 관련 백엔드 70개 테스트 통과.

## 남은 범위

HTML 링크·폼과 응답 헤더 기반 탐색이다. JavaScript가 만드는 요청, 브라우저 세션에서만 드러나는 경로, 깊은 크롤링, 포트 스캔은 포함하지 않는다. 기술 지문은 관측한 헤더의 추정치이며 취약점 확증 근거가 아니다. 승인된 고정 계획 모드는 실행 중 AI 재계획을 하지 않는다. 실제 운영 대상 사이트에 대한 검사는 이 변경의 테스트에서 수행하지 않았다.
