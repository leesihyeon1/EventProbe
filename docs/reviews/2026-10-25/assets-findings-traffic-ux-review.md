# 자산·발견·트래픽 UI 검토

검토일: 2026-10-25 (Asia/Seoul)

## 범위와 근거

현재 저장소의 index.html, assets.js, global_lookup.js, workspace.js와 관련 CSS 및 자산 색인 코드를 검토했다. 로컬 브라우저는 접근 토큰을 요구하여 실제 데이터가 표시된 화면의 시각 검증은 수행하지 못했다. 아래는 코드로 확인한 구조와 동작에 대한 검토이며, 실제 화면의 잘림·대비·사용성은 구현 후 별도 확인해야 한다. 애플리케이션 코드는 변경하지 않았다.

## 세 화면의 역할

| 현재 이름 | 실제 역할 | 제안 이름 | 제목 아래 설명 |
|---|---|---|---|
| Asset | 저장된 작업과 수동 요청에서 연결된 도메인·메서드·경로·쿼리 키 목록. 작업 선택 시 해당 작업의 사이트맵과 관측 상태 표시 | 자산·경로 | 지금까지 등록하거나 요청한 웹 경로와 관련 기록을 확인합니다. |
| 발견 | 검증 작업의 확증·의심·미확정 결과, 증거 수, 처리 상태, 관련 작업 조회 | 보안 발견 | 검증 중 기록된 보안 문제와 의심 항목을 검토합니다. |
| 트래픽 | 도구가 저장한 요청 기록과 HTTP 상태·출처 조회. 일부 작업 기록에서 요청·응답 상세 제공 | 요청 기록 | 도구가 보낸 요청과 수집한 응답 기록을 확인합니다. |

자산은 서버 장비 목록이 아니라 요청 경로 구조에 가깝다. 발견에는 확정되지 않은 항목도 있어 메뉴 전체를 '취약점'으로 부르면 오해를 만든다. 트래픽은 PC 전체 네트워크를 실시간 감시하는 화면이 아니다. 세 화면을 조회하는 것 자체가 새 대상 요청을 시작하지는 않는다.

## 확인한 문제와 수정 방향

### P1 — 역할과 데이터 범위가 드러나지 않음

- 세 페이지 모두 제목 다음에 바로 필터가 나온다(index.html:391 이후). 기능 설명, 데이터 출처, 다음 행동 안내가 필요하다.
- Asset에서 전체 작업과 특정 작업을 선택하면 기간·상태 필터의 활성 여부와 상세 의미가 달라진다(assets.js:loadAssetMap). '전체 자산'과 '작업별 사이트맵' 보기를 명시적으로 분리한다.
- 자산 필터는 해시 앞 12자만 표시한다(global_lookup.js:287). 사용자가 읽을 수 있는 `GET example.test /api/items`를 표시하고 내부 식별자는 상세에 둔다.
- 조회 범위와 상세 이력 범위가 다를 수 있다. 기간으로 좁힌 자산에도 전체 연결 이력이 나타나므로 '선택 기간에 요청된 자산 / 상세는 전체 연결 이력'을 구분한다.

### P1 — 발견 목록만으로 검토할 내용을 판단하기 어려움

- globalLookupRow는 URL을 주 제목으로 쓰고 유형·판정을 보조 텍스트로 표시한다. 심각도는 목록에 표시하지 않으며 처리 상태는 `open` 등 원래 값이 노출된다(global_lookup.js:200 이후).
- 목록은 '발견 유형 → 대상 경로 → 판정 → 심각도(기록된 경우) → 처리 상태 → 증거 수 → 최근 기록' 순으로 구성한다.
- 판정(확인 정도), 심각도(영향), 처리 상태(업무 진행)를 서로 다른 열과 배지로 구분한다. 의심을 높은 심각도로, HTTP 성공을 안전으로 변환하지 않는다.
- 행 선택 시 같은 화면의 상세 패널에서 판단 근거와 연결 증거를 먼저 보여주고, 관련 작업 이동은 보조 동작으로 둔다.

### P1 — 자산 트리가 기본 탐색에 과도한 공간을 사용

- CSS는 가지마다 160px 폴더, 24px 간격, 240px 노드를 가로 배치한다(sitemap.css:7 이후). 깊은 경로는 가로 이동이 커질 수 있으며, 현재 트리에는 접기 기능이 없다.
- 기본은 도메인별 접을 수 있는 목록/표, 우측은 선택 경로 상세로 구성한다. 트리 보기는 보조 보기로 유지한다.
- 작업 목록 페이지와 자산 목록 페이지가 각각 이전/다음 버튼으로 표시된다. 작업 선택은 검색 가능한 선택기로 바꾸고 자산 목록 페이지 이동만 본문 하단에 둔다.

### P1 — 상태 선택 HTML 오류

- index.html:409의 `</option value="discovered">`는 시작 태그가 아니라 잘못된 닫는 태그다. `value="discovered"`인 정상 option으로 수정해야 한다.
- 수정 후 '발견·미요청' 옵션이 실제 DOM에 존재하고 해당 값으로 필터링되는지 확인한다. 현재 브라우저에서의 표시 결과는 미검증이다.

### P2 — 요청 기록을 비교하기 어려운 카드 구조

- 발견과 트래픽이 같은 카드 렌더러를 사용하고 각 행마다 이동·비교 버튼을 반복한다. 요청 기록에는 시간·메서드·도메인/경로·HTTP 상태·출처·원문 보유 여부를 정렬한 표가 더 적합하다.
- 요청·응답 상세는 이벤트 JSON을 그대로 출력한다(global_lookup.js:234). 저장된 데이터가 있는 범위에서 '요약 / 요청 / 응답 / 원본 데이터'로 구분한다.
- 수동 요청 등 메타데이터만 저장된 기록은 '요약만 저장됨'을 명시한다. 상세가 없는 이유를 버튼 부재만으로 전달하지 않는다.
- 현재 비교는 출처·메서드·주소·HTTP 상태·시각만 비교한다. 동작 이름은 '요약 비교'로 표시하고 요청/응답 본문 비교로 오해하지 않게 한다.

### P2 — 필터·빈 상태·오류 안내 개선

- 검색과 핵심 필터를 기본 줄에 배치하고 기간·출처·보관 여부 등은 추가 필터로 묶는다. 적용 조건은 해제 가능한 칩과 '모두 초기화'로 표시한다.
- '저장된 기록 없음', '필터 결과 없음', '조회 실패'를 분리한다. 각각 데이터 생성 경로 안내, 필터 초기화, 재시도 동작을 제공한다.
- 로딩·오류 중 이전 결과를 현재 조건의 결과처럼 보이지 않게 한다.
- 세 화면의 제목 크기·콘텐츠 폭·여백·행 높이·페이지 이동 위치를 통일한다.

## 제안 화면 구성

공통: 메뉴와 제목 → 역할 설명 → 현재 범위/검색/주요 필터 → 목록 → 선택 항목 상세.

- 자산·경로: 도메인별 목록 + 메서드/경로/관련 기록 수 + 선택 자산의 요청 기록·보안 발견 연결.
- 보안 발견: 유형/대상/판정/심각도/처리 상태/증거 수의 목록 + 판단 근거와 증거 상세.
- 요청 기록: 시간순 표 + 요청/응답 상세 + 최대 두 건의 요약 비교.

관련 기록으로 이동할 때 자산과 기간·보관 범위를 눈에 보이게 유지한다. '같은 자산의 기록'과 '이 발견에 직접 연결된 증거'는 구분해 표시한다. 서로 같은 경로라는 이유로 증거 연결을 추정하지 않는다.

## 구현 순서와 완료 기준

1. 메뉴·제목·설명·처리 상태 번역, 해시 대신 경로 표시, 상태 option 오류 수정.
2. 자산 기본 목록과 작업별 사이트맵 분리, 세 화면의 검색·필터·빈 상태 통일.
3. 발견과 요청 기록을 각각의 목적에 맞는 목록과 상세 패널로 재구성.
4. 범위 유지 및 뒤로가기, 키보드 탐색과 모바일 상세 전환 확인.

관련 건수·판정별 요약·서버 정렬 등이 현재 API에 없는 경우 별도 조회 설계가 필요하다. 현재 페이지 50건을 전체 건수나 전체 통계로 표시하지 않는다. 실제 저장되지 않은 심각도·원문·응답 시간을 만들어 표시하지 않는다.

완료 기준: 처음 보는 사용자가 각 화면의 목적과 데이터 출처를 설명할 수 있고, 목록에서 항목 선택 후 화면 이동 없이 핵심 내용을 확인하며, 어떤 자산/기간을 보는지 항상 알 수 있어야 한다. 1366px 데스크톱과 390px 모바일에서 긴 경로, 빈 데이터, 원문 없는 기록, 오류 상태를 확인한다. 조회/상세 열기는 새 검증 실행을 유발하지 않아야 한다.


## 구현 결과 (2026-10-25)

- 메뉴와 페이지 제목을 자산·경로 / 보안 발견 / 요청 기록으로 통일하고 설명을 추가했다.
- 전체 자산과 작업별 사이트맵을 분리했다. 도메인별 접이식 목록을 기본으로 제공하고 기존 경로 트리를 선택할 수 있다. 선택한 작업은 직접 링크에 복원된다.
- 발견·요청 목록을 표로 구성하고 같은 화면의 상세 영역에서 내용을 확인한다. 발견은 판정·심각도·처리 상태·증거 수를 구분하며 연결 증거는 펼칠 때만 원문을 조회한다.
- 요청 상세는 요청/응답/원본 이벤트로 나눴다. 수동 요약 기록의 원문 부재를 명시하고 기존 메타데이터 비교를 '요약 비교'로 표시한다.
- 추가 필터를 접을 수 있게 하고 적용 필터 칩·초기화·조회 오류 재시도를 추가했다. 필터 변경 시 이전 목록과 상세를 지우며 늦게 도착한 상세 응답은 새 선택을 덮어쓰지 않는다.
- 자산 필터에는 결과의 읽을 수 있는 경로를 표시한다. 자산↔요청 기록 이동에는 기간·보관 범위를 전달하고, 기간 필터가 없는 발견 화면과의 이동에서는 보관 범위를 전달한다.
- '발견·미요청' option 문법을 수정했다. 실제 실행/검증 동작이나 백엔드 저장 정책은 변경하지 않았다.

검증: 프런트엔드 173개 테스트 통과, JavaScript 구문 및 diff 공백 검사 통과. 별도 루프백 미리보기 서버의 합성 example.test 기록으로 데스크톱과 390×844 모바일에서 목록, 연결 증거 펼치기, 자산→요청 기록, 원문 없는 요청 상세를 확인했다. 모바일 문서 너비는 390px로 유지되며 표 내부만 가로 스크롤한다. 실제 운영 데이터와 인증 세션을 이용한 브라우저 검증은 하지 않았다. 프런트엔드 파일 변경이므로 기존 서버 재시작 없이 브라우저 새로고침으로 적용된다.
