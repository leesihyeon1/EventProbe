# ARTEX → EventProbe 이식 3단계: 독립 발견·증거 보존

작성일: 2026-11-08. 대상: `C:\Users\shlee\dev\sec-api-tester`.

## 적용 범위

실행 기록에 종속돼 있던 발견과 증거를 사용자가 선택하여 별도로 보존하는 기능을 추가했다. ARTEX 전체 기능의 100% 통합 완료를 뜻하지 않는다. 기존 실행 큐·모델 라우팅과 EventProbe의 발견·보고서·재검증 구조에 연결했다.

- 발견 상세의 **증거 별도 보존**으로 저장하고 **보존한 발견**에서 검색·조회한다. 모든 실행을 자동 보존하지 않는다.
- 별도 UUID 식별자를 사용하며 원본 실행 ID와 기존 발견 ID를 출처로 보존한다. 같은 자료의 재보존은 중복 버전을 만들지 않는다. 원본 변경 시 최신 revision을 확인하여 새 불변 버전을 추가한다.
- 상태·심각도·메모는 원본과 별개로 관리한다. 변경 이력과 동시 수정 충돌 검사를 제공한다. 과거 버전 조회에도 현재의 독립 분류 상태를 함께 표시한다.
- 관련 action·observation·verification을 스냅샷으로 보존한다. 본문은 상세에서 선택하여 불러오며 보고서·요약 ZIP·보존 관측 ZIP을 제공한다.
- 원본 실행 삭제나 retention 정리 후에도 보존 증거를 조회·보고서화·내보내기·재검증할 수 있다. 별도 삭제는 이 발견의 모든 버전과 연결을 제거한다. 원본 실행·다른 보존 발견·이미 생성한 재검증 실행은 삭제하지 않는다.

## 저장 및 무결성

`saved_evidence.py`의 독립 테이블과 내용 해시 기반 SQLite BLOB을 사용한다. 보존·삭제·참조 정리를 한 트랜잭션으로 처리하고 여러 발견이 공유하는 본문은 마지막 참조가 없어질 때 논리 삭제한다. DB 파일은 커질 수 있으며 논리 삭제만으로 물리 파일 크기가 즉시 줄어들지는 않는다. 파일 기반 저장소·본문 스트리밍은 이번 범위가 아니다.

발견/출처 메타데이터, 스냅샷 메타데이터와 본문 길이·SHA-256을 검증한다. 손상되거나 누락된 기존 증거를 자동으로 덮어써서 복구하지 않는다. 해시는 우발적 손상을 감지하며 출처의 진위나 악의적 재작성 여부를 인증하지 않는다.

한 버전은 10 MiB·250개 이벤트, 한 발견은 100개 버전·10,000개 분류 변경 이력으로 제한한다. 보존 시 원본을 읽고 증거를 저장하는 과정, 삭제와 공유 본문 정리는 각각 트랜잭션으로 직렬화된다.

## 개인정보·접근 범위

보존 관측은 기존 관측 자료이므로 원래 잘렸거나 정제된 내용을 완전한 원문 트래픽으로 복구하지 않는다. 인증 관련 헤더는 기존 정제 규칙으로 제거하며 원본 실행 명세의 헤더도 보존하지 않는다. URL/query·요청 본문·응답 본문의 값은 보존될 수 있다. 보존 및 원본 값이 포함되는 내려받기 화면에서 이를 안내한다. 보존 관측 ZIP은 완전한 MITM/네트워크 원문 캡처를 뜻하지 않는다.

본문 열기·수정·삭제·내보내기·가져오기·재검증에 기존 작업공간 접근 규칙을 적용한다. 소유권 검사는 해당 DB 트랜잭션 안에서도 수행한다. 소유 범위가 활성화된 경우 새 보존/가져오기는 작업공간 이름을 요구한다. 기존 공용 토큰과 사용자가 지정하는 작업공간 이름 방식은 실제 사용자 인증 체계로 교체되지 않았으며, 소유자 없는 과거 자료에 대한 기존 접근 규칙도 유지한다.

## 별도 복원 패키지

`archive.zip`은 발견의 모든 보존 버전·분류 변경 이력·스냅샷·본문과 manifest 해시를 담는다. 가져오기는 ZIP을 디스크에 풀지 않고 파일명·중복·크기·형식·참조·해시를 검사한 뒤 한 트랜잭션으로 저장한다. 소유자는 가져오는 현재 작업공간으로 설정하며 발견 식별자 충돌은 덮어쓰지 않는다. 가져오기 자체는 실행이나 AI/대상 요청을 생성하지 않는다.

압축 파일 25 MiB, 전체 내용 50 MiB, 1,024개 항목까지 지원한다. 기존 실행 아카이브 v1에는 이 독립 보존 라이브러리가 포함되지 않는다. 별도 복원 패키지나 전체 DB 백업이 필요하다. 이 패키지에는 재검증 실행 및 연결 이력은 포함되지 않으므로 필요하면 실행 아카이브/DB를 별도로 보관해야 한다.

## 재검증

보존 당시의 판정은 그대로 두고 새 실행을 만든다. 고정 confirm 계획과 AI 호출 한도 0을 사용한다. 원본 실행이 삭제되어도 실행할 수 있다. 새 실행과 보존 버전 연결을 먼저 원자적으로 저장한 뒤 기존 실행 큐에 넣는다.

과거 인증 헤더나 현재 편집기의 인증 정보를 자동으로 복사하지 않는다. API는 새 요청/actor 헤더를 명시적으로 받을 수 있으며 기본 UI는 비어 있는 새 세션으로 요청한다. 원본 본문이 있으면 다시 입력해야 하고, GET/HEAD 외 메서드는 쓰기 요청을 명시적으로 허용해야 한다. 원본 URL 및 query 값은 재사용하므로 민감한 값과 실제 요청 대상에 유의해야 한다.

기존 발견 재검증과 같이 첫 관련 action의 위치·파라미터를 사용한다. 모든 파라미터를 재검사하는 기능은 아니다. 지원 범위는 confirm 계획이 있는 sqli/auth/xss/ssti/lfi/ssrf/cmdi/redirect/nosql이며 access/OOB 등은 포함하지 않는다. 재검증 실행을 삭제하면 이력은 증거 없음·현재 판정 미확인으로 표시한다.

## 검증 및 적용

백엔드 전체 회귀 테스트 **1,346개 통과**(경고 3개), 프런트엔드 전체 테스트 **187개 통과**. 신규 백엔드 보존·복원·재검증 테스트는 24개, 신규 화면 테스트는 5개다. 테스트는 외부 통신을 차단하고 임시 DB·합성 관측만 사용했다. 실제 브라우저의 시각적 검증은 수행하지 않았으며 화면 동작은 Node DOM 테스트로 확인했다. 적용한 대상 파일의 재검증 결과는 ARTEX 분석 폴더의 `implementation-result-evidence-2026-11-08.json`에 별도로 기록한다.
