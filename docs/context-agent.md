# 맥락 에이전트

현재 요청에서 시작해 관측 → 가설 → 실행 → 검증을 반복하는 HTTP 테스트 에이전트입니다.
기존 NVIDIA/AI 설정을 사용합니다. LLM은 다음 행동을 선택하고 실제 영향 판정은 코드가 담당합니다.

## 사용

1. 요청 / 분석 화면에 시작 URL, 파라미터, 헤더와 본문을 입력합니다.
2. 상단 **맥락 에이전트**를 열어 목표와 한도를 설정하고 **현재 요청으로 시작**을 누릅니다.
3. 기본 한도는 8단계, 대상 HTTP 요청 24회, AI 호출 8회, 누적 실행 시간 300초입니다.
4. 관측된 같은 출처의 링크·GET 폼과 리다이렉트 경로가 다음 탐색 후보가 됩니다.
5. 각 카드에서 가설, 원본 요청·응답, 계정/세션 ID, 증거 ID, 검증 결과를 펼쳐 확인합니다.
6. **중단**으로 일시정지하고 **재개**로 이어갑니다. 한도 도달 시 새 실행을 만들어야 합니다.
   AI가 종료를 선택했다는 것은 전체 앱이 안전하거나 목표를 완전히 달성했다는 뜻이 아닙니다.

쓰기 메서드(POST/PUT/PATCH/DELETE)는 별도 체크해야 사용할 수 있습니다.
HTTP 메서드가 GET이어도 대상 기능이나 주입 값에 따라 상태가 바뀔 수 있습니다.
실제 HTTP 전송 직전에 예산을 소비하며 오류·중단된 요청도 포함합니다. 리다이렉트는 자동 추적하지 않습니다.
AI 호출은 숨은 재시도 없이 한 번씩 계산합니다. OOB 등록·폴링은 대상 HTTP 한도와 별개이며
실행 시간 한도 내에서 처리합니다(대기 행동당 최대 3회 폴링).

## 계정과 객체 정책

첫 계정은 현재 요청의 인증 헤더를 이어받습니다. 다른 계정은 독립된 헤더·쿠키 저장소를 사용합니다.
Set-Cookie로 회전한 쿠키를 이어받고 같은 계정에서 관측한 HTML 폼의 CSRF/VIEWSTATE 값을
다음 요청의 기존 필드에 반영합니다. 자동 재로그인과 브라우저 로그인 조작은 지원하지 않습니다.

계정 예:

```json
[
  {"id":"A","label":"사용자 A","headers":{"Authorization":"Bearer <A 토큰>"}},
  {"id":"B","label":"사용자 B","headers":{"Authorization":"Bearer <B 토큰>"}}
]
```

객체 정책 예(실제 소유권과 접근 정책을 알고 있을 때 등록):

```json
[
  {
    "id":"orderB",
    "url":"https://your-test-app.example/orders/42",
    "owner_actor":"B",
    "allowed_actors":[],
    "identity_pointer":"/id",
    "identity_value":"42",
    "description":"이 주문은 사용자 B만 조회할 수 있음"
  }
]
```

에이전트가 `access` 행동을 선택하면 소유자 응답과 권한 없는 계정의 응답 2회를 비교합니다.
세 응답이 모두 200이고, 지정한 JSON Pointer 값으로 같은 객체임이 확인될 때
정책에 어긋난 **해당 객체 1건의 읽기 접근**으로 기록합니다. 실제 정책 자체의 정확성은
사용자가 제공한 정보에 의존합니다. 응답 일부가 잘렸거나 객체 식별이 불가능하면 미확정입니다.

## 판정과 기억

- `observe`: 응답 관측과 같은 출처의 탐색 후보 수집.
- `probe`: 정상 요청과 동일 주입 요청 2회를 비교. 단순 반사·SQL 오류·응답 지연은 성공 확정하지 않습니다.
- `confirm`: 기존 차등 프로브 묶음을 두 회차 실행하고 공통 확증 결과를 기록. 두 회차 예산이 없으면 한도로 종료.
- `access`: 명시한 객체 소유권 정책 검증.
- `wait_oob`: 테스트별 마커 콜백 관측. 콜백 자체로 데이터 접근이나 명령 실행을 확정하지 않습니다.
- `finish`: 더 진행할 행동이 없으면 종료. 가설 문장은 증거가 아닙니다.

실행·요청·관측·가설·검증·콜백을 SQLite에 저장합니다. 원본 증거와 파생 판정을 ID로 연결하며
다른 실행의 증거 ID를 사용하거나 같은 행동을 반복하면 중단합니다. 전후 상태나 쓰기 권한의
검증까지 일반화된 엔진은 아직 없으며, 객체 정책 검증은 읽기만 지원합니다.

단일 요청 화면의 XSS 확증은 고유 마커를 사용하고 계정 헤더·메서드·본문을 브라우저에 전달합니다.
반사만 관측한 경우나 일반 페이지 알림은 XSS 확증이 아닙니다. 에이전트 실행기는 브라우저
하위 요청까지 포함한 예산 제어가 준비되지 않아 브라우저 도구를 직접 호출하지 않습니다.

## 저장과 재시작

- 기본 DB: `backend/data/agent/runs.sqlite3` (`AGENT_DB_PATH`로 변경 가능, Git에서 제외).
- 알려진 인증 헤더·쿠키는 저장/AI 헤더에서 제외하고 프로세스 메모리에 유지합니다.
  URL·본문의 비밀정보까지 완전히 익명화하는 기능은 아닙니다. 로컬 증거와 내려받은 JSON에는 응답 데이터가 포함됩니다.
- 서버를 재시작하면 진행 상태는 `interrupted`가 됩니다. 인증이 필요했던 실행은 요청/계정 헤더를 다시 지정해 재개해야 합니다.
  자동으로 생성된 로그인 세션은 새로 로그인해 받은 인증정보가 필요합니다.
- 단일 서버 프로세스를 기준으로 합니다. 동일 DB를 공유하는 여러 worker 실행은 지원하지 않습니다.
- OOB 마커/암호화 세션은 프로세스 메모리이므로 재시작 이전 마커는 이어서 폴링할 수 없습니다.
  저장된 콜백 증거는 남습니다. 기본 도메인 직접 방문은 특정 에이전트 테스트에 귀속되지 않습니다.
- AI에는 기본적으로 경로·필드명·판정 라벨·검증 결과만 제공합니다. **응답 발췌 전달**을 켜면
  최근 관측의 응답 앞부분도 전달합니다. 타깃 응답과 RAG 자료는 실행 지시가 아닌 데이터로 취급합니다.


모의 HTTP/AI로 범위 이탈, 예산, 계정 분리·쿠키 회전, 증거 귀속, 중단·재개, 객체 식별,
오탐 방지와 저장을 검사합니다. 실제 NVIDIA 모델의 CTF 해결률은 별도 실험으로 측정해야 합니다.
