# 이벤트 분석 구현 현황

2026-11-01: 제안서 1~2단계의 읽기 전용 MVP 구현.

- 왼쪽 이벤트 분석 메뉴에서 로그 파일/붙여넣기 → 서버 분석 → 대상별 시간창 묶음 → 상세 필드/우선순위 필터 → JSON 내보내기.
- `/api/triage/analyze`는 최대 2MB/10,000건을 처리하며 서버에 배치를 저장하지 않는다. 대상 요청과 AI 호출은 없다.
- CEF, 인용 key/value WAF·IDS, JSON 배열/NDJSON 및 httpHost 또는 _raw로 시작하는 CSV를 지원한다. 다른 CSV 컬럼 순서/벤더 포맷은 추가 어댑터가 필요하다.
- 시간대를 포함한 ISO 시각은 15분 묶음으로 분류한다. 다른 시각 표기/시각 누락은 레코드별 보완 묶음이다.
- PCAP은 디코딩하지 않고 미분석 표시한다. 원문 필드와 탐지 문자열은 텍스트로 출력한다.
- 테스트: 벤더 동작/횟수, IDS 중첩 필드, 호스트 충돌, 오류 행, 혼재 증거, 4xx 예외, 용량/API 경계.

후속 범위: 벤더 시각/CEF severity 정규화, 광범위 CSV 어댑터, 중복 가져오기 이력, 자산 인벤토리 연결, 사용자별 저장/보존, 검증 계획과 실제 실행 연결, 수동 우선순위 변경 이력. 현재 화면은 이를 완료한 것으로 표시하지 않는다.

서버가 reload 없이 실행 중이면 백엔드 재시작 후 신규 API를 사용할 수 있다.


## 2차 구현: 자산 대조와 선택 검증

- 이벤트 상세에서 운영자가 확정한 URL을 입력하여 기존 관측 엔드포인트와 정확히 대조한다. 기존 작업공간 소유권 범위를 적용하며 미등록 자산을 저우선으로 강등하지 않는다.
- `/api/triage/prepare`는 GET 쿼리 요청에 대해 지원 유형·주입 키·URL을 검사하고 사건 계약과 최대 요청 수를 반환한다. 대상 요청/AI 호출/사건 저장은 없다.
- UI에서 계획과 요청 수를 확인하고 승인하면 기존 사건 생성 및 재검증 API를 호출한다. 이 시점에 사건과 실행 기록을 저장한다. 실행 링크로 기존 진행·중지·결과 화면에 연결한다.
- 인증 포함 URL, 중복 쿼리 키, fragment, 비 HTTP URL, 지원하지 않는 유형/파라미터는 준비 단계에서 거부한다. GET 외 메서드·본문 기반 요청은 수동 검토 안내를 표시한다.
- 로그 호스트에서 프로토콜을 임의 추정해 실행하지 않는다. 확정 URL은 사용자가 입력하며, 로그 자격정보는 재사용하지 않는다.
- 실행 실패 시 만들어진 사건을 유지해 같은 사건에서 재시도할 수 있다. 완료 이후 재검증 결과는 기존 사건 상태를 따른다.
- 입력을 수정하면 기존 계획 승인을 무효화하고 준비 응답 대기 중 수정된 입력에도 이전 계획을 적용하지 않는다.
- 검증: 분석·계획·자산·사건 회귀 테스트 총 58개 통과. JS 문법/Python 컴파일 검사 통과. 실제 대상 요청은 수행하지 않았다.

남은 범위는 운영 인벤토리의 중요도/스택/최신성 관리, 원문 보존/배치 저장, 벤더별 시각 및 포맷 확장, 중복 수집 관리, 우선순위 변경 이력이다. 새 화면은 현재 기존 엔드포인트 이력 대조를 제공하며 완전한 CMDB로 표시하지 않는다.


## 3차 구현: 운영 인벤토리와 선택 보관

- 운영 인벤토리 CSV 등록/갱신/조회/삭제: origin,service,contact,importance,stack,environment,verified_at. 500개까지 한 번에 검증하며 오류가 있으면 해당 가져오기를 전체 거부한다.
- origin 호스트가 하나의 자산에만 일치하고 호스트 충돌이 없을 때 연결한다. 30일 초과 확인 정보는 오래됨으로 표시한다. 신선한 high 자산은 정보 보완에서 검토 필요로 승격할 수 있지만, 미등록/오래된 자산은 감점하지 않는다.
- 분석 기록 저장은 선택 사항이다. 기본 7일, 1~30일 지정 가능하며 원문과 분석 결과를 함께 저장한다. 작업공간당 최대 100개 배치다.
- 동일 원문 SHA-256의 작업공간 내 중복 저장은 같은 기록을 반환하며 기한을 연장하지 않는다. 교차 파일은 파싱된 원본 필드의 fingerprint로 겹치는 이벤트 수를 표시하고 삭제하지 않는다. 장비 간 같은 통신 여부의 상관분석과는 다르다.
- 저장 기록 조회/불러오기/삭제를 제공한다. 불러온 결과는 저장 당시 정책/자산 정보 기준임을 화면에 표시한다.
- 만료 기록은 실행 중 60초 주기와 기록 접근 시 정리한다. 서버 중지 중에는 정리되지 않으며 다음 실행 때 정리한다. 삭제는 SQLite 논리 삭제이며 별도 백업/디스크 복구 방지까지 보증하지 않는다.
- DB 기본 경로는 기존 agent DB 옆 triage.sqlite3이며 TRIAGE_DB_PATH로 분리할 수 있다. 기존 agent DB 스키마는 변경하지 않는다.
- 작업공간 식별은 기존 ep_user / x-eventprobe-user 방식과 일치한다. 조회/삭제/중복은 해당 값으로 분리한다. 이 값은 자체 인증 수단이 아니며 공용 토큰 사용자 간 강한 격리를 의미하지 않는다.
- 로그 분석 자체는 여전히 대상 요청/AI 호출을 발생시키지 않는다. 일반 분석이 임시 입력을 자동 보존하지 않으며, 인벤토리 조회를 위해 빈 저장소 파일은 생성될 수 있다.

남은 확장: 벤더 시각/CEF 메타데이터 파싱 보강, 다양한 CSV 어댑터, 이벤트 우선순위 수동 변경 감사, 장비 간 요청 상관분석, 인증된 개인별 접근 체계.


## 대응 중심 UI 및 일괄 테스트 연결

- 로그 가져오기 → 종합 판단 → 대상별 접속 주소 확인/이벤트 선택 → 다중 대상 일괄 테스트로 연결한다. 분석 후 입력 영역은 접고 종합 판단을 앞에 표시한다.
- 종합 판단은 차단/허용/불명 분포, 검토 필요/정보 보완/재요청 저우선과 권장 대응을 규칙으로 요약한다. 침해 성공을 추정하지 않는다.
- 검토 필요 일괄 선택 또는 개별 선택을 지원한다. 저우선도 사용자가 직접 선택할 수 있다.
- 확정 origin을 입력해야 하며 GET 요청만 연결한다. 동일 URL은 1개로 합치되 원본 이벤트 연결은 모두 보존한다. 경로를 이용한 origin 이탈과 잘못된 URL은 전달 전에 거부한다.
- 기존 일괄 테스트의 다중 대상 화면에 URL을 채우고 GET/직접 입력 페이로드 없음/동시 1로 준비한다. 실제 전송은 사용자의 기존 테스트 시작 버튼으로 실행된다. 요청 헤더는 기존 설정을 사용하므로 화면에서 확인하도록 안내한다.
- 다중 테스트 완료 시 실제 실행 URL과 매칭한 원본 이벤트에 응답 코드/시각을 표시하고 bulkResults에 출처 연결을 남긴다. 연결은 현재 브라우저 세션 기준이며 저장된 분석 배치에 자동 소급 반영하지 않는다.
- 검증: 순수 UI 흐름 테스트(요약, 선택, 중복, 잘못된 origin/경로/메서드 거부) 및 JS 문법 검사 통과. 실제 대상 요청은 수행하지 않았다.


## 분석표와 검증 후보 중심으로 재구성

- 이벤트 카드를 대상/요청, 탐지 내용, 장비 처리/응답, 분석 판단, 레코드 수의 표로 교체했다.
- 동일 host/method/path/signature/action/status/priority의 로그를 묶고 검토 필요를 먼저 정렬한다. 다른 쿼리 값은 보존한다.
- 원문 전체 URL 또는 로그의 명시적인 scheme/80·443 포트로 접속 주소를 복원한다. 호스트 충돌/PCAP 미확인은 자동 복원에서 제외하고 보완 입력으로 남긴다.
- 접속 주소가 복원되는 검토 필요 GET 이벤트는 자동 선택한다. 저우선은 자동 선택하지 않는다. 사용자는 분석표에서 예외를 선택할 수 있다.
- 일괄 테스트는 선택된 요청을 전달하며 기존 실행 버튼에서 시작한다. 검증 결과 응답 코드를 원래 분석표에 표시한다.
- 행별 별도 파라미터 검증 폼은 주 화면에서 제거했다. 기본 흐름은 분석표 확인과 일괄 테스트 연결이다.


## 대량 스캔 대응: 행위 묶음

- 대상/출발지 × 고정 15분 시간창으로 관측 이벤트를 묶는다. 10레코드·5경로 이상을 넓은 경로 탐색으로, 같은 대상 3출발지·5경로 이상을 여러 출발지 탐색 후보로 표시한다. 출발지 한 곳의 3자산 이상 탐색과 10레코드·3유형 이상 탐색도 표시한다.
- 숫자는 초기 휴리스틱이며 입력 파일 내 관측치다. 중복 레코드, NAT/프록시, 시간창 경계와 수집 누락의 영향을 받는다. 실제 캠페인/동일 공격자 확정 기능은 아니다.
- 차단·허용·불명 분포 및 운영 대응 안내를 제공한다. 전부 차단된 묶음은 대표 재요청을 추천하지 않는다. 그 외에는 허용 또는 검토 필요 GET 요청에서 최대 3개를 선정하고 선택 버튼으로 기존 일괄 테스트에 연결한다.
- AI 사용 여부는 로그만으로 판별 불가로 표시한다. 빠른 적응형 요청 생성, 장기 저속 탐색, 교차 파일/장비 상관분석은 아직 구현하지 않았다.
- 근거: MITRE Active Scanning https://attack.mitre.org/techniques/T1595/ 및 Wordlist Scanning https://attack.mitre.org/techniques/T1595/003/ . AI 공격 도구 활용 동향 참고: Microsoft https://www.microsoft.com/en-us/security/blog/2026/03/06/ai-as-tradecraft-how-threat-actors-operationalize-ai/ . 이 동향을 AI 사용 판별 규칙으로 전용하지 않는다.
